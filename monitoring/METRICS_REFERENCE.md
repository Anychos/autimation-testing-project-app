# Справочник метрик TaskFlow

Используемые в дашбордах и правилах ряды перечислены ниже вместе с метриками приложения. Prometheus добавляет `job` и `instance` ко всем scraped-сериям. Для histogram экспортируются `_bucket` с дополнительным `le`, `_sum`, `_count`; Python exporter также может добавлять служебный `_created`. UUID, email, идентификаторы событий и SQL-текст в бизнес-лейблы не входят. Маршруты без совпадения записываются как `__unmatched__`, нерегулярные методы как `OTHER`. Health и `/metrics` исключены из HTTP статистики; подключения для health входят в пул.

Коэффициент cache hit равен `rate(pg_stat_database_blks_hit[2m]) / (rate(pg_stat_database_blks_hit[2m]) + rate(pg_stat_database_blks_read[2m]))`. При отсутствии операций за окно значение может быть NaN. Для анализа PostgreSQL 17 по reads/writes доступен `performance/sql/io_statistics.sql`. PostgreSQL exporter показывает block read count и накопленное block read/write time. Детальные данные `pg_stat_statements` остаются в PostgreSQL и доступны через диагностический SQL.

Для CPU и latency сравнивайте одинаковые окна и одинаковые границы buckets. Квантиль вычисляйте после объединения счётчиков, с разбиением по маршруту только для endpoint-панелей. Расчёт `-deriv(taskflow_outbox_pending[2m])` показывает чистую скорость сокращения backlog в событиях/с. Положительное значение означает, что публикаций больше, чем новых записей.
